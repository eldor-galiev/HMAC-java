# HMAC Message Signing Service (Java)

Минималистичный микросервис на Java для обеспечения целостности и аутентичности сообщений с помощью алгоритма **HMAC-SHA256**.

---

## Описание проекта
Сервис реализует механизм симметричной подписи сообщений. Это позволяет убедиться, что данные не были изменены в процессе передачи и отправлены именно тем, кто владеет общим секретом.

**Основные возможности:**
* **HMAC-SHA256**: Гарантирует целостность и аутентификацию.
* **Base64URL**: Подпись передается в безопасном для URL формате без паддинга (`=`).
* **Constant-time comparison**: Защита от атак по времени при проверке подписи.
* **Безопасное логирование**: Секретные ключи никогда не попадают в логи.

---

## Конфигурация
Настройки хранятся в файле `config.json`. Перед запуском убедитесь, что файл находится в корневой папке проекта.

```json
{
  "hmacAlg": "SHA256",
  "secret": "your-base64-encoded-secret",
  "listenPort": 8080,
  "maxMsgSizeBytes": 1048576
}
```
**Параметры:**

* hmacAlg: Алгоритм хеширования (рекомендуется SHA256).
* secret: Секретный ключ, закодированный в Base64.
* listenPort: Порт, на котором сервер принимает входящие запросы.
* maxMsgSizeBytes: Лимит размера сообщения в байтах для защиты памяти.

## Генерация секрета для config.json (HMAC key)
HMAC использует симметричный секретный ключ. Он должен храниться в защищённом виде и не передаваться клиентам.

### На shell (Linux / macOS)
```bash 
  openssl rand -base64 32
```

### На Java
```java
KeyGenerator keyGen = KeyGenerator.getInstance("HmacSHA256");
keyGen.init(256);
SecretKey key = keyGen.generateKey();
String base64 = Base64.getEncoder().encodeToString(key.getEncoded());
```

Чтобы скомпилировать проект, выполните команду:

## Ротация секрета (CLI)
Для удобного обновления секретного ключа предусмотрен shell-скрипт. 
Он автоматически генерирует новый ключ и обновляет `config.json`. 
Запускать его необходимо в корне проекта.
```Bash
  ./cli/rotate-secret.sh
```
После обновления ключа необходимо перезапустить приложение для его применения нового секрета.

## API и примеры curl
Все запросы должны использовать заголовок `Content-Type: application/json`.

### 1. Подписать сообщение (POST /sign)
Генерирует цифровую подпись для строки.

**Запрос:**
```bash
  curl -sS -X POST http://localhost:8080/sign \
    -H 'Content-Type: application/json' \
    -d '{"msg":"hello"}'
```

**Ответ (200 OK):**

```json
{
  "signature": "mOh56vGH6xe35N8utbPLvbi5A5LGzzsi5AuACkA0hlo"
}
```

### 2. Проверить подпись (POST /verify)

Проверяет целостность сообщения и подлинность отправителя.

**Запрос:**

```bash
    curl -sS -X POST http://localhost:8080/verify \
      -H 'Content-Type: application/json' \
      -d '{"msg":"hello", "signature":"<ваша_подпись>"}'
```

**Успешный ответ (200 OK):**

```json
{ 
  "ok": true
}
```

**Если подпись неверна (200 OK):**

```json
{ 
  "ok": false
}
```

## Логирование

События работы сервиса (запуск, ошибки валидации, успешные операции) записываются в файл `hmac-server.log` в корне проекта.

**Особенности реализации:**
* **Безопасность**: Полные значения секретного ключа и тел сообщений в логи не выводятся (только длина или статус операции).
* **Формат**: Каждая запись содержит метку времени, уровень логирования (INFO/ERROR) и описание события.

## Ограничения учебной реализации

Данный проект разработан в образовательных целях. При использовании в реальных системах следует учитывать следующие ограничения:

1. **HMAC vs Асимметричная ЭП**:
    * Используется симметричный алгоритм (один ключ для подписи и проверки).
    * Это не является юридически значимой электронной подписью, так как отсутствует свойство **неотказуемости** (non-repudiation): любой, кто может проверить подпись, технически может её и создать.
2. **Отсутствие инфраструктуры доверия**:
    * В системе не используются сертификаты (X.509), метки времени (Timestamp) и цепочки доверия (CA).
3. **Управление ключами**:
    * Ротация секрета реализована через перезапись локального файла `config.json`. В распределенных системах это требует синхронизации между всеми узлами.
4. **Конфиденциальность**:
    * HMAC обеспечивает только **целостность** и **подлинность**. Тело сообщения (`msg`) передается в открытом виде и не зашифровано.
